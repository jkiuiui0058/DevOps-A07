# C 端失败记录

## 统一容器首次运行失败

### 现象

统一运行日志停在：

```text
=== RESTORE B BUNDLE ===
```

容器状态为 `exited`，退出码为 `1`。最初的宿主侧 `exit-code.txt` 被错误记录为 0，因此最终判断以 `docker inspect` 的容器状态为准。

### 原因

脚本在 `/lab` 下直接执行：

```bash
git bundle verify /lab/B/repository.bundle
```

但 `/lab` 不是 Git 仓库，实际错误为：

```text
error: need a repository to verify a bundle
```

### 修复

脚本改为先从 bundle 克隆仓库，再在恢复后的仓库中执行校验：

```bash
git clone /lab/B/repository.bundle "$B_WORK"
git -C "$B_WORK" bundle verify /lab/B/repository.bundle
```

重新构建镜像后，统一容器完成全部步骤并以退出码 0 结束。

### 证据

- `evidence/unified/failed-container-inspect.json`
- `evidence/unified/failed-container-summary.txt`
- `evidence/unified/failed-output/incremental/bundle-verify.log`
- `evidence/unified/image-rebuild-after-bundle-fix.log`
- `evidence/unified/replay-after-bundle-fix.log`
- `evidence/unified/container-summary-success.txt`

## 契约脚本路径失效

### 现象

WSL 中执行 `scripts/validate_contracts.py` 时返回退出码 1，并报告找不到：

```text
docs/examples/full-check/request.json
```

### 原因与修复

仓库已经将 E2 内容移动到 `E2/`，脚本仍使用旧的 `docs/examples/` 路径。将本仓库样例路径改为 `E2/examples/` 后，五个正例通过，缺少 baseline 的反例被拒绝。

## 证据目录未预先创建

首次保存 Docker 构建、镜像和工具信息时，宿主侧重定向目标目录不存在，导致日志未写入。镜像构建本身成功。创建 `evidence/environment`、`evidence/md-rd` 和 `evidence/incremental` 后重新采集，最终证据完整。

## 处理原则

- 失败证据保留，不覆盖或伪装为成功记录。
- 修复后生成独立日志和退出码文件。
- 容器结果以 `docker inspect` 中的 `State.ExitCode` 为最终依据。
- WSL、独立 Docker 和统一 Docker 的日志分目录保存。
