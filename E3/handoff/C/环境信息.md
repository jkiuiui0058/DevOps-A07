## 统一复现环境决策

### 已确定

- C 端统一复现优先采用 Docker，而不是直接在当前 Windows 宿主机上运行。
- 统一基础镜像采用 `ubuntu:24.04`。
- 容器内统一工作目录采用 `/work`。
- 容器内至少安装以下工具：
  - `build-essential`
  - `git`
  - `make`
  - `bash`
  - `ca-certificates`
  - `python3`
  - `strace`

### 决策理由

- A、B 当前提交的 `Dockerfile` 都以 `ubuntu:24.04` 为基础镜像，统一成本最低。
- 当前宿主机是 Windows + Git Bash，文件时间戳、路径分隔符和工具行为可能影响 GNU Make 的复现结果。
- E3 任务安排明确要求 C 固定 Linux/Docker 环境并记录工具版本，因此应以 Linux 容器作为正式复现实验环境。

- 工作目录：`/work`

### B

- 基础镜像：`ubuntu:24.04`
- 已安装：`build-essential`、`git`、`make`
- 工作目录：`/work`
- 默认入口：`bash`

### C 的统一化处理

- 以后续 C 自建环境为准，不直接沿用 A 或 B 任一方的容器作为最终统一环境。
- C 的统一环境需要在 A/B 的共同基础上补齐：
  - `python3`
  - `strace`
  - `ca-certificates`
- 后续复现时需要在容器内补采以下精确版本：
  - `gcc --version`
  - `make --version`
  - `git --version`
  - `python3 --version`
  - `strace -V`
