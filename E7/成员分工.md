# E7 任务分工

仅使用 A、B、C 标识。本组全部任务属于 BuildChecker 的 A 轨道。依据 E7 PPT、两份 E7 手册、A 轨道指南、验收清单与 CI-A 闭环记录整理.

## 分工与交付方向

| 分工 | 独立负责的一整块工作 | 最终交付 |
|---|---|---|
| A | 全部本地验证：三次重复、修复、三类故障、完整八项 gate | 本地验证成品包 → C |
| B | 完整远程 CI 门禁：接入、首次成功、保护、同一 PR 失败与恢复合并 | CI 门禁成品包 → C |
| C | 独立判定测试、验收准备；最后接收两份成品，集成、总结和归档 | 最终报告、验收表、源码与证据归档 |

 C 前期完成自己的判定测试和汇总结构，最后统一接收材料。CI 从接入到恢复全部由 B 独立完成，不拆成跨人流水线。

三人从同一已确认 E6 基线开展工作。B 可基于该基线与自己的贡献完成远程演示，不等待 A/C 新增测试；C 收齐后再集成全部贡献并验证最终版本。共享仓库的 main 和保护规则仍然有效，独立工作不等于绕过规则。

状态初始均为 TODO。DONE 必须附实际产物和结果；验收尚无结果填 PENDING，阻碍写明日志和下一步，不将预期填成实际。

## 独立工作的边界

- A 修改自己的服务测试与 `E7/A/`；B 修改自己的服务测试、workflow、保护/演示辅助文件及 `E7/B/`；C 修改独立判定测试、`E7/C/`、总报告及清单。公共脚本确需修正时说明文件和原因，避免重复修改。
- 各自使用独立克隆、Git 身份、`e7-a` / `e7-b` / `e7-c` 分支、独立镜像标签及全新 work 输出目录。共享小内存主机构建错峰，代码和写作可并行。
- 三人各新增一项测试，保留个人 commit/PR、目的/输入/预期/实际、源码 SHA、镜像 ID 与备份位置；修改后重建镜像，各自在本人版本完成定向测试、独立判定与完整 gate。测试数按实际日志，不照抄 15/16。
- B 负责共享仓库保护与演示，提前确认管理员权限。若必须由管理员代执行配置，仅协助权限动作，B 仍承担准备、核验和留证。不得绕过保护。
- B 的闭环记录对应 B 执行时的版本，C 的最终正常 CI 对应集成版本，报告分别标明，不冒充同一 SHA。最终改动若影响门禁行为或规则，先修复并按影响范围补验，不能只凭旧记录认定最终通过。

## A/B 统一交给 C 的成品包

1. 可合并的代码/测试 PR、完整提交 SHA、来源说明。
2. 可直接拼入报告的成稿、验收 CSV 行和已知限制。
3. 已备份且 C 可获取的完整证据、清晰索引、实际命令与退出码、源码 SHA 与镜像 ID，不只提供被忽略的 work 路径。
4. A 额外交三次集合比较、输入哈希/diff、八项 gate 和原始 trace；B 额外交正常/失败/恢复 artifact、规则快照、拒绝日志和最终合并记录。

C 负责接收、集成和验收；缺项由原负责人补齐，不转给另一个角色。

## 完整八项 gate 标准

| case | 预期结果与通过条件 |
|---|---|
| unit-tests | 当前服务测试全部通过，退出 0，数量按实际记录 |
| original-1/2/3 | 每次 SUCCEEDED、clean/build=0、CLI=1；精确两条 MD/RD，各有证据锚点；三次源输入相同 |
| fixed | SUCCEEDED、clean/build=0、CLI=0、findings=[]；源输入仅 Makefile 哈希变化 |
| build-failed | FAILED、CHECK_FAILED、CLI=1，真实构建退出码非零 |
| unsupported | FAILED、UNSUPPORTED、CLI=1，构建本身成功 |
| timeout | TIMED_OUT、TIMEOUT、CLI=1，保存超时记录 |

原始三次分别计行，共八项；整体退出 0、八行 passed=true，JSON/CSV 一致。每场景填输入、预期、实际、状态、退出码、判定和证据。成功分析保存两图、processes、Make 数据库、trace；逐场景保存输入副本、命令、stdout/stderr 和 findings。

现场展示：A 讲本地与故障，B 讲 CI 与同一 PR 失败/恢复，C 讲独立判定、最终版本与证据索引；三人各讲新增测试价值。教学小型样例验证不代表原论文全量基准，环境故障与注入故障分别记录，归档不含令牌、认证文件或私钥。
